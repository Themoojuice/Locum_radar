# Source acquisition: towards national locum coverage

**Research date: 13 October 2026.** Figures marked _retrieved_ were read from the live source on that date; figures marked _recalled_ are from background knowledge and need checking. Counts change daily.

**Implementation update, 14 October:** This document retains the earlier source research. The [acquisition guide](acquisition-plan.md) is the current implementation reference: it includes resumable HTML/feed/sitemap collectors, selected-label Gmail OAuth, recent search leads, a live Ochre smoke test and source restrictions. Dedicated agency adapters remain available alongside these collectors. Earlier “needs an adapter” statements below describe the research snapshot, not the current code.

## Summary

- **There is no national locum feed, and "every locum vacancy at every hospital" is not an observable set.** Hospitals release most short-term medical cover to agencies on state supplier panels, to direct-booking platforms, or to their own casual pools. Public hospital job boards mostly advertise employed (temporary, casual or permanent) roles. The achievable target is near-complete coverage of what agencies and platforms publish, plus what reaches the inbox, with coverage measured rather than assumed.
- **Only one documented public job-search API is usable here: Adzuna.** It is an aggregator, returns description excerpts only, and allows about 250 calls a day by default. It is a discovery aid, not a primary source.
- **The practical "APIs" are the structured endpoints behind agency job boards.** Wavelength serves clean JSON, 1Medical exposes a WordPress REST index, Medrecruit embeds full job records in its pages, and several agencies publish schema.org `JobPosting` data. Access to each is governed by that site's terms, not by technical availability.
- **The largest source, Medrecruit, prohibits bulk screen scraping in its terms.** Its weekly email digests are the compliant channel until it grants permission or a feed.
- **The inbox is already the richest permitted source.** About 200 locum threads arrived in the past 12 months, dominated by two agencies, and one digest or table email typically carries 15–40 vacancies.
- **A national hospital directory was the main blocker to automated review, and it has an open API.** The Australian Institute of Health and Welfare (AIHW) MyHospitals API lists 1,121 open hospitals with coordinates and sector. Resolving advertised names against it raised fully valid records on real samples from 0/15 to 11/15 (Medrecruit) and from 5/42 to 24/42 (1Medical).

### Inbox (read-only scan, 13 October 2026)

- A search for `locum` over 12 months returned about 200 threads.
- **Medrecruit** marketing digests arrive once or twice a week. Each lists 10–20 vacancies as `Facility – Role` headings with `dates | roster | rate | travel` rows, under state headings, and states a super rule once (NSW rates plus super; other hourly rates include it). Dates have no year. There are no listing IDs.
- **1Medical** recruiters send either a single-vacancy alert in prose or a seven-column table (state, start, end, shifts, hospital, job title, pay). One table email held 42 rows.
- LinkedIn job alerts are the only other recurring source. No other agency currently emails this inbox, which says more about sign-ups than about the market.

## Collection workflow

Each tier feeds the existing review queue. Nothing is committed without review, and every source needs recorded permission before automatic collection, as the architecture already requires.

**Tier 1 — inbox (now).**

1. Sign up for job alerts at every agency on the NSW register that offers them, using a dedicated address such as `you+locum@gmail.com` (Gmail plus-addressing, _recalled_). This turns permission-restricted boards into a permitted channel.
2. Install `scripts/gmail-export.gs` as a Google Apps Script in the same account. Every two hours it copies matching messages to a Drive folder as `.eml` files. It reads mail and creates files only.
3. Sync that folder with Google Drive for desktop, then run `npm run import-mail -- <folder>` (or schedule it). Recognised formats are split row by row; everything else goes through the existing conservative parser.
4. Alternative: a Gmail API integration with OAuth. It removes Drive from the path, but `gmail.readonly` is a restricted scope, and an unpublished "Testing" app's refresh tokens expire after seven days (_recalled_). Apps Script avoids both problems for one person.

**Tier 2 — permissioned structured sources (days to weeks).** Email Wavelength, 1Medical, Medrecruit and Medlo with the request below. Record the reply as permission evidence, then enable the adapter. Run daily, newest first; the JSON collector stops at the first page with nothing new, so routine runs make one to three requests.

**Tier 3 — long-tail agencies (weekly).** For WordPress, Bullhorn and SourceFlow sites, read the sitemap, fetch only new or changed job pages, and parse `JobPosting` data, honouring robots and terms per site. Fewer than ten agencies probably carry most of the volume (judgement); prioritise by unique suitable vacancies, not advertisement count.

**Tier 4 — state boards (weekly).** Sitemap differences filtered to medical categories and "temporary", "casual" or "locum" in the title. Expect few short locums but some useful fixed-term and registry-of-interest roles.

**Tier 5 — gated platforms.** StatDoctor, the Medlo app and similar platforms stay manual. Their notification emails flow through Tier 1.

**Tier 6 — discovery.** Adzuna once a day (four pages at most) to find agencies and postings missing from the source registry. Treat hits as leads.

**Normalisation used by every tier.**

- Resolve facility labels against the AIHW directory (`npm run import-facilities`). Matching prefers public hospitals, refuses ties, and records each resolution as a review note.
- Keep source mistakes visible. In one real 1Medical table, 5 of 42 rows ended before they started (year typos). The parser flags them and does not "correct" them.
- Deduplicate conservatively. The panel model means the same vacancy is often advertised by several agencies with different rates. The existing reconciliation rules apply; the next useful addition is candidate generation by facility, grade and overlapping dates, sent to review.
- An optional model-based fallback for unrecognised formats is possible, but this repository deliberately sends no source text to a language model. If added, it should run only on unrecognised emails, cite the source span for each field, and never commit automatically. (Judgement.)

## Measuring coverage

Count unique suitable vacancies per source and the overlap between sources. With two sources, the Chapman form of the Lincoln–Petersen estimator gives the total as (n₁+1)(n₂+1)/(m+1) − 1, where m is the number matched in both (_recalled_, standard ecology method). Agencies are not independent (they answer the same hospital requests, and urgent rural roles are listed more widely), so positive dependence biases this low; treat it as a lower bound. With three or more sources, log-linear capture–recapture models can estimate and adjust for some of that dependence. The useful output is a trend in estimated recall per source, not a single total.
